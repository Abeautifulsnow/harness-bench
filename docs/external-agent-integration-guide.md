# 外部 Agent 平台接入指南

> 读者：要把一个**外部自研 Agent 平台**接入 harness-bench 评测的人（shim 作者）。
> 契约基线：PRD §6–§8（接入协议与事件词汇）、Spec §19.1.2（三结局通则）、
> §12.1.1/§12.4（观测面透传与缺口可见义务）。
> 本文是 PRD §6.3"shim 模式"的操作手册；首个接入平台（ai-chatbot/Sime）的
> 逐条坐标与四轮评审校准见
> `docs/external-agent-integration-change-plan.md`（§2/§8）。

---

## 0. 接入形态与分界线

```text
harness-bench（框架，通用） ←—— HTTP+SSE 四端点 + §8 事件词汇 ——→ 转译 shim（接入侧，每平台一份） ←—— 平台原生 API ——→ 被测平台
```

- **框架与接入方的分界线只有一条**：`AgentAdapter` 四方法 + PRD §8 事件词汇表。
  平台特有的东西必须在 shim 里归一化成 §8 词汇，框架不感知平台是谁。
  框架源码受专有方言边界测试约束（`tests/test_framework_boundary.py`）——
  往框架里塞平台分支会被测试拦下，别往那个方向努力。
- **shim 是测试侧组件**：不进被测平台的生产代码与构建产物，建议放在
  被测平台的 `tests/` 或独立目录。
- **平台不代管被测方的基础设施**（PRD §3.2）：容器化、数据播种、环境重置
  是接入方/运维的义务；框架只负责 fixture workdir 的透传与清理。

---

## 1. 第一步永远是冒烟（第 0 步）

在写任何 shim 代码之前，先用 30 行脚本直连被测平台的原生 API，钉死**运行时
行为**。静态事实（端点、字段、常量）可以读源码核实，但以下五类只能实跑确认：

1. 事件流 chunk 的实际**顺序与时序**（开场/收尾 chunk 是什么、数据 part 夹在何处）；
2. 鉴权/许可失败发生在 **HTTP 状态码**（流前）还是流内 error chunk；
3. 人机审批触发后，本轮是否以正常的收尾 chunk 结束（等待在客户端）；
4. 关联 id（如子任务事件与父工具调用的 id）是否真的相等；
5. 用量数据出现的**时机与频率**（每轮一次还是每个增量一次，带哪些分量）。

映射表的"顺序与时序"部分在冒烟通过之前应视为**高置信推断**，不是事实。

## 2. 四端点契约（shim 对上要实现的）

| harness-bench 调用 | shim 必须返回 | 要点 |
| --- | --- | --- |
| `GET /health` | `{"status":"ok"}` | 必须真检查：license/许可前置、模型配置、workdir 可达性。**在此上报观测面能力表与实际生效模型**（见 §3）。health 报 ok 而 run 报鉴权失败，会被框架归为基础设施故障（exit 2）而不是"许可证过期"——两类故障必须在 health 上就能区分 |
| `POST /api/agent/sessions` | `{"session_id": ..., "workdir_accessible": bool}` | 接受 `metadata`（平台键 + 扩展键 `workdir`，PRD §7.2）；**可达性回执必须走响应体**——请求 metadata 是回显，SUT 写不进去。不可达回 `false`（框架按配置错误处理，exit 2）；探测不了就别回（框架记 warning，未知 ≠ 可达） |
| `POST /api/agent/sessions/{id}/run` | SSE 流，每条 `data:` 是一个 PRD §8 事件 JSON | 核心转译，见 §4。请求显式携带模型标识（不依赖被测平台默认值） |
| `POST /api/agent/sessions/{id}/cancel` | `200` | 尽力而为收尾；run 结果已定时不影响结论 |

会话语义：一次 `create_session` = 一个 case 的一个 iteration，iteration 之间
零共享（Spec §2.4）。shim 必须为每个会话分配**独立**的临时工作区，迭代后清理。

---

## 3. 观测面能力声明（§12.1.1/§12.4 的接入方义务）

在 `/health` 响应里声明被测平台**能提供哪些 PRD §8 观测面**：

```json
{
  "status": "ok",
  "observation_surface": {
    "tool.call": true,
    "mcp.call": true,
    "retry": false,
    "context.compaction.started": false
  },
  "agent_model": "platform-actually-running-model"
}
```

三条规则：

1. **只声明事实**。被测平台结构性地不发某事件（如重试只写日志、不上协议流）→
   声明 `false`。框架会让依赖它的 metric 判 `skipped`（可见、不阻断、不计入
   分母）——这比恒 pass 诚实，比删 profile 条目可追溯。
2. **不声明 = 具备**。空表按全具备处理（框架的 FakeAgent/mock server 路径
   行为不变）。声明是**接入侧的否决权**，不是框架的猜测——框架绝不从
   "事件没出现"反推"观测不到"。
3. **缺口要登记**。哪些观测面缺失、为什么、处置是什么——写进本指南的
   实例清单（模仿 change-plan §B2 的表），使覆盖缺口可评审（Spec §12.4）。

`agent_model` 是被测方自报的**实际生效**模型，它会进入 `RunMetadata` 并参与
基线守卫：两次 run 模型标识不一致，回归比较直接判 INVALID——所以请如实上报，
别把请求参数原样抄回来。

## 4. 事件转译（核心工作）

### 4.1 归一化原则

- 每个平台方言事件**必须**映射到 §8 词汇；映射不到的要么丢弃（并解释为什么
  可丢），要么推动框架升级词汇表（PRD §8 是闭合清单，走框架升级）。
  私造事件名会被词汇校验拦下：默认档 warning，strict 档 exit 2。
- **逐观测面拆分，不得折叠**：MCP 调用 → `mcp.call`/`mcp.result`（哪怕方言里
  只是普通工具调用）；独立命令 → `command.started`/`command.finished` 并带
  `exit_code`。折叠进 `tool.*` 的后果是安全规则与 MCP 权限规则**恒 pass**
  ——这是本仓库记录过的最严重缺陷类别（Spec §12.1.1）。
- `run.finished` 必须可靠发出：流提前结束且没有 `run.finished` 会被判为
  agent 失败。
- **"丢进 §8 流"与"可以不留档"是两件事**。有一类方言的用途不是报告，而是**回话**：
  续跑要重建 assistant 消息时缺了它，模型侧会拒收整条消息。先例：思考令牌
  （reasoning）整族被丢弃后，每次审批续跑都以"必须把 reasoning 回传"的流内 error
  收场——形态是**一次成功的提问在报告里变成 agent 崩溃**。判据：丢一个事件类型之前
  先问"它是不是平台侧协议的一部分（请求体里要回传的东西）"，而不是只看"§8 词汇表里
  有没有它的位置"。两者都否才可以丢。

### 4.2 映射表模板（首例列来自首个接入平台，随平台漂移，以冒烟实测为准）

| §8 事件 | 方言来源（示例） | 转译注意 |
| --- | --- | --- |
| `run.started` / `run.finished` | 会话开始 / 收尾 chunk + 结束标记 | 收尾必须成对出现，否则按 agent 失败结算 |
| `tool.call` / `tool.result` | 工具调用/结果 part | 参数已是对象 → 直接作 `data.arguments`；**参数类与安全类断言全靠它** |
| `tool.result`（错误/被拒） | 工具错误 / 权限拒绝 part | 被拒原因若在关联对象的 reason 字段，取回它，不要自行编造 |
| `mcp.call` / `mcp.result` | `mcp__<server>__<tool>` 形态的工具名 | **必须拆成独立事件**，不得折叠进 `tool.call` |
| `command.started` / `command.finished` | shell 类工具调用 | 退出码若埋在输出对象里，必须提到 `data.exit_code` |
| `subagent.started` / `subagent.finished` | 子任务开/合 data part | 关联 id 是否等于父工具调用 id——冒烟确认。**closing 事件必须挂在 opening 事件的 id 上**（框架按"配对 opening 的 event_id"建 span）：挂错位置会被当作孤立 closing 忽略，span 永不闭合，收尾时统一判成 error——一次成功的子任务在报告里呈现为失败。异步子任务（父流不会再有 done）要查终态表，**不得当丢事件，也不得合成一个假的 done**：合成等于替平台宣布一个尚未发生的结果，报告里"还在跑"与"跑完了"就同形了 |
| `skill.loaded` | skill 激活工具调用 | 有显式事件更好 |
| `model.response`（usage） | 用量 data part | 注意分量：只有输入侧时如实转译，output 侧缺失由框架按口径处理（§6） |
| `error` | 错误 chunk / 收尾状态为 error | 注意错误文本可能被平台自愈逻辑抑制为空串 |
| `retry` / `context.compaction.*` | **不可观测**（示例平台的实况） | 声明 `false`，框架判 skipped |

## 5. 人机审批 / 提问（如果平台有"等人"语义）

框架协议里没有"等人"：`run.finished` 一到就结算本轮。若被测平台的审批
语义是"流挂起、本轮正常结束、等待完全在客户端"，shim 必须定一个**自动策略**
（预置放行规则 / 自动批准 / 自动拒绝），且：

1. **策略必须写进 run 元数据，在报告里可追溯**——同一份用例在不同策略下测的是
   两个不同的系统，跨 run 比对会失去意义；
2. **审批的"答案"是测试输入，不是实现细节**：`ask_user` 类交互的回答会进入
   对话上下文并改变 agent 后续行为。会触发提问的多轮用例，用例作者必须声明
   "用户答什么"、shim 在正确时机注入——没设计答案的用例测的是随机性。
   这条要求要写进用例作者指南（change-plan §3 修订 6）。三条落地要点：
   - **答案的"键"是被问的那个问题本身**。首个接入平台实测：答案 map 里的键若不等于
     问题原文，平台**照样收下、不报错**，只是 agent 查不到 → 静默退化成"没收到答案"。
     因此 shim 应把配置的键（支持问题全文 / 短标题 / 序号三种写法）**归一成问题全文**
     再发；写错键时应当在 stderr 或流内留痕，不要静默。
   - **问了却没配到答案，默认不应放过**：缺口放过去，红的是 agent 的行为（它没收到
     答案自然不会照答案做），而报告里看不到真实原因——与"超时归属必须唯一"同源。
     建议默认让本轮流带**自述原因**失败，另留一个宽松档给探索性运行。
   - 答案多是**进程级**配置（shim 启动时给定）。按用例给不同答案要换实例——这条边界
     要如实写进 shim 的已知边界，别让用例作者以为它是 per-case 的。
3. 识别审批挂起时**以第一方形状为准**（工具 part 的 state 字段之类），
   并用冒烟实测确认——不要照抄类型声明文件里的字面串。
4. **续跑消息是"整条 assistant 消息"的重建，不是"只补一个审批 part"**：服务端通常
   按 message id 整体覆盖，因此这条消息里原有的叙述型 part（文本、思考）都要按原顺序
   带上。少带一类就可能是协议违约——首个接入平台的实况是模型侧直接 400，
   而不是静默丢弃。重建之后要核对**每类 part 的字段**：有的 part 类型本来就没有 id
   字段，凭空加键同样可能被 schema 拒绝。

## 6. 并发、副作用与用量口径

- **并发**：查清被测平台的并发/队列上限，shim 与 `--concurrency` 都必须压在
  容量之下（超限的"繁忙"错误会被判成 agent 失败），并把该上限记进 run 元数据。
- **副作用**：agent 会往 workdir 写自己的产物（日志/导出文件）。shim 解析轨迹时
  不得把 workdir 当工作区；每个 case 迭代后清理。用例侧的 `file_state` 断言
  要么限定 fixture 子集、要么过滤已知产物目录，否则会无端 FLAKY；
  产物采集（case-artifacts）同样会扫 workdir——"失败现场的干净"是用例作者的义务。
- **用量口径**：被测平台只上报部分用量分量时（常见：只有输入侧），shim 如实
  透传，不要用文本长度**估算**补齐——估算伪装成测量，违反"没有观测来源就
  不得评测"的底线。框架会记录口径（full/partial）并在基线比对时拦截口径
  不可比的两侧；依赖缺失分量的约束（如 `max_tokens` 依赖输出侧）自动判 skipped。
  子任务的用量若带全量三分量，单独注明——哪里有全量、哪里只有单侧要写清，
  别让后人误以为全链路都缺。

## 7. 交付前 checklist

```text
[ ] 第 0 步冒烟通过，五类运行时行为钉死并记录
[ ] 四端点全部实现；/health 真检查前置条件并上报观测面表 + 实际模型
[ ] workdir 回执走响应体；不可达/未知的语义分清
[ ] 映射表逐条对过冒烟实测（不是照抄类型声明）
[ ] MCP / command / 子任务 / 审批逐观测面拆分，无折叠
[ ] run.finished 可靠收尾；未知事件类型为 0（开发期用 --strict-protocol 跑过）
[ ] 成对事件（tool/mcp/command/subagent…）的 closing 挂在 opening 的 id 上——用真
    轨迹重建一次 span 树，确认没有 "span never closed" 的假 error
[ ] 所有**断言依赖的可选参数**都被提示词钉死：模型可自由填/不填的参数（如子任务
    指定的代理类型）会让同一条用例两次运行给出不同观测值，报告上却是"被测对象失败"
[ ] 异步语义（父流无终态的那种）不合成结果、也不留未闭合 span；终态若有独立接口，
    把形状记进 shim 文档并声明"未接进 §8 流"及理由
[ ] 审批答案按"问题原文"注入并可回读；缺口有留痕（默认不静默放过）
[ ] 审批策略已定义且进 run 元数据；触发提问的用例都设计了答案
[ ] **丢方言之前先问一句**：它是不是平台侧协议的一部分（续跑要回传的）？是就留档，
    不进 §8 流也要留档——先例：丢掉 `reasoning-*` 让每次审批续跑都被模型侧拒收
[ ] 预算类断言（"超时真的会红"）不与全局预算覆盖共存：这类 case 排到默认套件之外，
    别指望用预算语义解决它们的冲突
[ ] 并发压在被测平台队列容量下；上限已记录
[ ] 观测面缺口清单已登记（缺什么 / 为什么 / 处置）
[ ] 用例作者指南更新：工具名逐字一致、审批答案设计、file_state 过滤产物、
    超时按场景校准、结构性断言优先
```

两条来自首例接入的红线教训，写在最前面：

> **最大的风险不是"接不上"，而是"接上了却不报错"。** 观测面在转译时被偷懒
> 合并或忽略，对应指标会静默变成恒 pass——报告上"没有越权"与"根本没看到
> MCP 调用"长得完全一样。
>
> **开发期一直开 `--strict-protocol`。** 词汇笔误（`mcp_call` vs `mcp.call`）
> 在第一次就会拦下；等报告全绿之后靠人眼发现 `mcp.calls` 恒空，成本高一个量级。
